Built-in tools of the shared request: `WebSearch` (with `allowed_domains` and `user_location`) and `CodeExecution` go in `tools=` beside the functions and reach Anthropic as `web_search_20250305` and `code_execution_20250825`; a `ProviderTool` of this provider is sent as its own definition, and a tool Anthropic does not run raises `RequestValidationError`. The new `aiollm_anthropic.tools` module builds those provider tools for the rest: `web_search`, `web_fetch` and `code_execution`, with the dated version and Anthropic's own options (`blocked_domains`, `max_uses`, `max_content_tokens`, `citations`). The calls the provider ran come back as `server_tool_calls` (`server_tool_use` blocks with their results: `COMPLETED`, `FAILED` with the `error_code`, `INCOMPLETE` without a result) and the sources of the text as `citations` (a page of a search is a `URL`, a part of a stored file a `FILE`), in a response and in the `CompletedEvent` of a stream, where each call is also a `ServerToolCallEvent` when it starts and when its result comes. An `assistant` turn of `to_turn()` with Anthropic's own content goes back as that content, so the encrypted search results reach the next request.
